> Числа — [ЗАМЕРЫ](ЗАМЕРЫ.md). Оценки сроков помечены 💭: это догадки, не обязательства.

## Главный принцип этого графика

Мы построили конвейер раньше, чем описание того, что по нему течёт. Отсюда
все находки последних дней — это **одна ошибка в четырёх местах**: система не
знает, что за прибор прислал данные, и додумывает.

| Находка | Настоящая причина |
|---|---|
| Код канала зашит константой `HN` | описывать тип прибора негде |
| `sensorId >= 100` ломает архив | границы никем не заданы |
| СМ-3 некуда положить | нет понятия «тип прибора» |
| Три оси зашиты в конвейер | нет понятия «сколько каналов» |

Поэтому график идёт **снизу вверх**: сначала описание, потом то, что на нём стоит.
И между этапами стоят ворота — следующий не начинаем, пока предыдущий не держится.

## Этап 1 — фундамент: инвентарь знает приборы

💭 2–3 дня · **зависит от:** этап 0

Сейчас инвентарь ([DbStore.cpp:81](../src/storage/DbStore.cpp#L81)) хранит
`object_id, sensor_id, model, location` — этого мало, чтобы понять, что за прибор.

**1.1 Расширить инвентарь**
```sql
inv_sensors(object_id, sensor_id,
            uid,                     -- аппаратный ид кристалла: ключ сопоставления
            kind,                    -- accelerometer | seismometer | displacement
            channel_count,           -- 1..N, а не «всегда 3»
            model, location,         -- location = текст для человека
            valid_from, valid_to,    -- какой прибор стоял в какой период
            calibrated_at)

inv_channels(..., unit, gain,
            corner_period,           -- для СМ-3: где начинается завал
            orientation)             -- X/Y/Z для акселерометра, Z/N/E для сейсмометра
```

**1.2 Тип `StreamId`** — `network.station.location.channel` с проверкой лимитов
miniSEED v2 (2 / 5 / 2 / 3 символа, см. [ЗАМЕРЫ §6](ЗАМЕРЫ.md)). Ошибка ловится
при заведении в инвентарь, а не при записи на диск через три месяца.

**1.3 Код канала вычисляется, а не задаётся константой**

| Прибор | Частота | Код |
|---|---|---|
| Акселерометр | 200 Гц | `HNZ` |
| СМ-3 (T₀ ≈ 2 с) | 200 Гц | `EHZ` |
| СМ-3 | 50 Гц | `SHZ` |

**1.4 Незнакомый прибор отвергается.** Сейчас `tpacq --sensor 42` спокойно пишет
в архив несуществующий датчик. Отказ вместо догадки — одно условие, закрывает
целый класс ошибок.

**1.5 Число каналов из инвентаря.** Трёхосевые величины (JMA, векторное PGA)
считаются **только при трёх осях**. Для одноканального СМ-3 — честный отказ, а не
нули в две оси. Иначе система молча занизит интенсивность.

**Ворота:** акселерометр даёт `HN?`, СМ-3 даёт `EH?`, датчик вне инвентаря
отвергается с внятным сообщением.

## Этап 2 — замок: тест слоя «сохранить»

💭 1 день · **зависит от:** этап 1

Первый тест в сборке за всю историю проекта. Проверяет:

- записали N отсчётов → прочитали N, с теми же значениями
- сколько байт на отсчёт (фиксирует заполнение записи)
- `sensorId >= 100` — либо работает, либо честно отвергается на входе
- акселерометр → `HN?`, СМ-3 → `EH?`

**Ворота:** `tests/` в сборке, тест проходит, и с этого момента правило:
**новый модуль не считается готовым без теста своего слоя.**

## Этап 3 — закрыть измеренные дефекты

💭 1 день · **зависит от:** этап 2 (тест должен ловить регрессию)

**3.1 Заполнение записи miniSEED.** 📏 Сейчас 5.15 Б/отсчёт при несжатых 4.00 —
архив больше сырья. Причина: `TdsArchive(recordSamples = 200)`.
Сначала **замер** при 200 / 1000 / 4000, потом выбор по таблице. Ожидание 3–4× —
это 💭, и его надо превратить в 📏.

Компромисс осознанный: больше буфер = позже на диске. При обесточивании теряется
последнее незаписанное окно.

**3.2 Возобновление в `tpslink`.** Нет переподключения вообще; номер пакета из
заголовка `SL` разбирается и выбрасывается; шлём голый `DATA`. Значит после
обрыва теряется всё накопленное. Чинится по спецификации: хранить номер,
слать `DATA <seq>`.

**Ворота:** Б/отсчёт записан в [ЗАМЕРЫ](ЗАМЕРЫ.md) как 📏; `tpslink` после
минутного обрыва догоняет пропущенное.

## Этап 4 — время и несколько приборов

💭 3 дня · **зависит от:** этап 3

При одном датчике неверные часы — косметика. При десятках время это **единственное**,
что позволяет сравнивать каналы: вся структурная диагностика построена на том,
что датчик 3 и датчик 17 сдвинулись в один момент.

**4.1 Опорное время на узле.** Частота известна, прибор шлёт счётчик отсчётов →
отсчёт N находится в `t₀ + N/частота`. Точным должно быть только `t₀`.
Узел **периодически заново привязывает** время, а не интегрирует счётчик бесконечно:
кварц на 100 ppm даёт 0.36 с за час, привязка раз в минуту держит ошибку ~6 мс.

Базово NTP. GPS — опция, обязательная там, где нет сети (мост, плотина).

**4.2 Проверка на двух приборах физически.** Два процесса `tpacq`, два
переходника, один архив. Здесь вылезет то, чего мы не предусмотрели.

**Ворота:** два прибора пишут в один архив, времена сходятся, разрывов нет.

## Этап 5 — SeedLink-сервер на узле-сборщике

💭 1–2 недели · **зависит от:** этапы 1–4

Самый крупный пункт. Сырьё в центр — режим по умолчанию. **Отдельный процесс**
`tpslinkserver` (решение 2026-07-26, [АРХИТЕКТУРА §16](АРХИТЕКТУРА.md)) — не поток
внутри `tpacq`. Читает `raw.` с шины, держит кольцевой буфер недавних записей +
QTcpServer; более старое берёт из TDS-архива.

По опубликованной спецификации SeedLink: рукопожатие `HELLO / STATION / SELECT /
DATA / FETCH / TIME / END / BYE`, обрамление `SL` + 6 hex-цифр + 512-байтная
запись, 24-битные номера с переполнением, курсор на соединение и возобновление
с запрошенного номера, селекторы `LLCCC.T`, `INFO` как XML внутри miniSEED,
уни- и мульти-станционный режимы, ограничения на соединения.

⚠️ Писать **только по спецификации** — см. правило в [CLAUDE.md §1](../CLAUDE.md).
Наш клиент `tpslink` уже сделан так и работает с реальным сервером.

**Почему последним, а не сейчас.** Сервер отдаёт наверх ровно те записи, чью
идентичность задаёт этап 1.3, чьё время ставит этап 4, чьё заполнение чинит
этап 3.1. Построить его раньше — отдавать записи со старым `HN`, кривым временем
и на 20 % полные. Он идёт поверх готового основания.

**Ворота:** центральный `tpslink` берёт поток с Hub; сторонний SeedLink-клиент
читает его же; после обрыва догоняет по номеру.

## Дальше, вне этого графика

Не начинаем, пока этапы 0–5 не держатся:

| Что | Почему потом |
|---|---|
| Инструмент настройки приборов | нужен, когда есть свой прибор; читает/пишет калибровку, метку монтажа |
| Zero-touch развёртывание Hub | обретает смысл при десятках Hub |
| Source-абстракция (RS-485, Ethernet, LoRa) | когда десятки приборов на одной паре |
| Раздача конфига через `cfg.` | группа зарезервирована, не используется |
| Согласование версии схемы при подключении | защита от порчи данных разными версиями |
| Группы сообщений из конфига | сейчас `constexpr`, новая группа = пересборка всех модулей |
| GNSS как датчик смещения | акселерометром медленные деформации не измеряются |
| Плагинный ABI | единственная концепция SeisComp, которой нет |
| Переделка GUI, дерево вместо списков | при масштабе список не работает |
