## Коротко

📏 **33 исполняемых файла** (29 модулей + 4 smoke-теста) и 12 библиотек, полная
сборка зелёная, весь конвейер проверен вживую
на реальном акселерометре (STM32 по UART, `bad=0`, архив без разрывов).
Архитектура повторяет SeisComp: **8 из 9 официальных концепций реализованы**
(локаторы осознанно не берём — датчик стоит на месте).

## 1. Ядро: брокер и платформа

| Что | Состояние |
|---|---|
| **tpmaster** — центральный брокер (XSUB/XPUB), группы, очереди production/playback, встроенный dbstore | ✅ |
| **Write-before-notify** — сначала персист, потом рассылка | ✅ |
| **Только мастер пишет в БД**, клиенты read-only | ✅ |
| Снимок данных для тонких клиентов (control-порт 5563) | ✅ |
| **10 групп сообщений**: `raw. saf. wfp. shf. evt. qc. soh. cfg. inv. jrnl.` | ✅ |

### Платформа `tp::client::Application`
Единая точка входа для всех демонов (как в SeisComp «modules»):
- publish/subscribe, авто-heartbeat, `handleMessage(topic, header)`
- `handleRawMessage` — байт-в-байт пересылка (релей)
- `beforeBatch/afterBatch` — одна SQL-транзакция на пачку (хранилище)
- `pollIntervalMs` — тесный опрос для raw-потока
- `publishThenQuit` — режим одноразовых инструментов
- `storeForwardCap` — буфер при падении брокера
- messaging-обёртки: `message / journal / notifier / endpoints / connection`

**15 из 17 приложений** — наследники `Application`.
`tpmaster` осознанно на прямой шине (он *есть* шина), `tpconfig` — GUI.

## 3. Обработка

| Модуль | Что считает |
|---|---|
| **tpproc** | окна → RMS/энергия/**собственная частота (FFT)**/health → аномалии (SAF/SHF) |
| **tpevent** | группировка аномалий в события структуры (open → extend → resolved) |
| **tpwfparam** | **PGA, PGV, спектр отклика (5%), JMA-интенсивность (計測震度)** |
| **tpqc** | качество данных: разрывы, задержка, спайки, доступность |

**Реальные результаты на приборе:**
- собственная частота `fX = 2.28 Гц` (то, на чём стоит прибор)
- `PGA = 44.3 gal`, `JMA = 3.50 (震度 3)`
- качество `GOOD, avail 100%, gaps 0`

**Ключевые алгоритмы:**
- Настоящий **FFT** (KissFFT, окно Ханна, параболическая интерполяция) — на симуляторе тон 3.1 Гц читается как **3.11 Гц**
- Собственная частота считается по **отдельному длинному буферу** (точность), детекция — по короткому окну (скорость)
- **STA/LTA с гистерезисом** — на чистом сигнале **0 ложных срабатываний**
- **Nigam-Jennings** для спектра отклика

## 5. Конфигурация

- **Слои**: `etc/defaults` → `etc` → `~/.terrapulse` → флаги CLI ✅ (проверено: 100 → 256 → `--window 64`)
- **Привязки и профили**: `etc/key/sensor_<obj>_<sen>` → `profile_highrise.cfg` ✅

## 6. Распределённость и передача волн

| Модуль | Что делает | Проверено |
|---|---|---|
| **tprelay** | форвард выбранных групп на другой tpmaster | ✅ наверх ушли события, **0 строк сырья** |
| **tpslinkserver** | **SeedLink-сервер**: `raw.` с шины → кольцо → TCP | ✅ волны `TerraPulse → TerraPulse` |
| **tpslink** | SeedLink-клиент: приём + **переподключение с resume** | ✅ переживает падение сервера |
| **tpws** | REST/JSON + **живой SSE-поток** + `/api/waveform` из архива | ✅ |
| **tphubmon** | HTML-страница статуса (модули UP, качество) | ✅ |
| **store-and-forward** | буфер при падении брокера | ✅ backlog 840 → 0 |

**SeedLink-поток закрыт полностью** (спецификация — `SEEDLINK-PROTOCOL.md`):
обрамление 520 Б + 24-битная нумерация, хэндшейк `HELLO/STATION/SELECT/DATA/END`,
real-time по курсору на клиента, возобновление `DATA <seq>`, SELECT-селекторы
(`HN?`, `!`-негатив), multi-station в одном сокете. Ядро (`SeedLinkRing`) под
юнит-тестом; сервер, resume и селекторы проверены вживую.

**Сквозной поток данных проверен целиком (2026-07-26).** Один прогон всех
модулей вместе:
```
приём 6772 → анализ saf=357 → PGA=5.9 gal JMA=2.45 → качество avail 100% gaps=0
      → архив 3 файла miniSEED → SeedLink-сервер → клиент records=72
```
Волны, ушедшие через SeedLink, вернулись на шину и **прошли полный анализ как
второй датчик** — доказательство сквозного пути через транспорт.

## 8. Консоль (GUI)

Страницы: Dashboard · Monitoring (tprttv) · Map (tpmap) · Objects · Sensors ·
Analysis · Events (tpolv) · Settings. Плюс отдельные виды через `--view`.

Выведено в интерфейс: живые трассы X/Y/Z, спектр, **震度/PGA/PGV**, **график
спектра отклика**, качество данных по датчикам, сгруппированные события,
разбор волны из архива вокруг аномалии, офлайн-карта.

> ⚠️ Оформление признано неудачным — **переделка внешнего вида запланирована**.
> При масштабе также потребуется дерево вместо списков (см. `МАСШТАБИРОВАНИЕ.md`).

## 9. Соответствие концепциям SeisComp

| Концепция | Статус |
|---|---|
| Messaging (брокер, группы, нотификаторы, очереди) | ✅ один-в-один |
| Modules (демоны, control-скрипт, жизненный цикл) | ✅ |
| Database (единственный писатель, read-only клиенты) | ✅ |
| Waveform archives (SDS→TDS, RecordStream) | ✅ |
| Inventory (иерархия, bindings ≠ inventory) | ✅ |
| Configuration (слои, профили, update-config) | ✅ |
| Magnitudes → **интенсивность** (sensor→structure rollup) | ✅ адаптировано |
| Locators | ✅ осознанно не берём (датчик стоит на месте) |
| **Plugins** (динамическая загрузка, фабрика) | ❌ фасад есть, ABI/загрузчика нет |

**Чистая комната подтверждена:** код SeisComp не копировался. Наши заголовки в
4–8 раз меньше, стиль другой; повторена только организация (это факт, не объект
авторского права).

## 10. Проверено на реальном железе

```
[tpacq] COM6 @ 460800 baud  ->  topic 'raw.1.1.1'
[tpacq] connected=1 bytes=68119 published=1584 packets=1584 bad=0
```
- **bad = 0** — CRC сходится на всех пакетах
- **200 Гц, 0 разрывов** в архиве
- Полная цепочка: сбор → анализ → собственная частота → интенсивность → качество

**Найденная проблема (не блокер):** RTC прибора не синхронизирован с ПК, поэтому
метрика задержки в `tpqc` бессмысленна (разрывы и доступность — корректны).
Лечится синхронизацией времени прибора.
